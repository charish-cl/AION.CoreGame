# 编程规范

## 1. 命名空间规则（重要！）

### 1.1 必须引入类型命名空间
- **所有使用的外部类型必须引入对应的命名空间**
- 如果类型找不到，必须检查是否缺少 `using` 语句
- 如果项目中没有该类型，必须告知用户

**示例：**
```csharp
// ❌ 错误：缺少命名空间
public class MyClass
{
    private List<int> items; // 错误：List<> 需要 using System.Collections.Generic;
}

// ✅ 正确：引入命名空间
using System.Collections.Generic;

public class MyClass
{
    private List<int> items; // 正确
}
```

## 2. 属性访问规则（重要！）

### 2.1 属性访问权限检查
- **不能直接访问只读属性（只有 getter 没有 setter）**
- 如果属性没有公共的 setter，必须使用对应的设置方法
- 例如：`GameActor.Position` 是只读的，必须使用 `SetPosition()` 方法

**示例：**
```csharp
// ❌ 错误：尝试设置只读属性
tower.Position = worldPos; // 错误：Position 只有 getter

// ✅ 正确：使用设置方法
tower.SetPosition(worldPos); // 正确
```

## 3. 方法访问权限规则（重要！）

### 3.1 方法访问权限设计原则
- **public**：供外部类调用的公共方法，必须明确设计意图
- **private**：仅内部使用的私有方法，外部不应访问
- **protected**：供子类继承使用的方法
- **internal**：同一程序集内可访问

### 3.2 方法访问权限检查清单
在调用方法前，必须检查：
1. **方法是否为 public**：如果不是 public，不能从外部调用
2. **方法签名是否匹配**：参数类型和数量必须匹配
3. **是否需要重载版本**：如果需要无参数版本，必须提供重载

**示例：**
```csharp
// ❌ 错误：尝试调用 private 方法
public class WorldDragDrop
{
    private Vector2 GetWorldPosition(PointerEventData eventData) { ... }
}

// 外部调用（错误）
Vector2 pos = dragDrop.GetWorldPosition(); // 错误：方法不存在或不可访问

// ✅ 正确：提供 public 重载版本
public class WorldDragDrop
{
    // public 版本：供外部调用（使用当前鼠标位置）
    public Vector2 GetWorldPosition()
    {
        return GetWorldPosition(Input.mousePosition);
    }
    
    // private 版本：内部使用（使用 PointerEventData）
    private Vector2 GetWorldPosition(PointerEventData eventData)
    {
        return GetWorldPosition(eventData.position);
    }
    
    // public 版本：供外部调用（使用屏幕坐标）
    public Vector2 GetWorldPosition(Vector2 screenPosition)
    {
        // 实现...
    }
}

// 外部调用（正确）
Vector2 pos = dragDrop.GetWorldPosition(); // 正确：public 方法
```

### 3.3 方法访问权限设计建议
1. **提供便捷的 public 重载**：如果内部有带参数的方法，考虑提供无参数或常用参数的 public 版本
2. **明确方法用途**：public 方法应该有清晰的文档注释，说明使用场景
3. **避免过度暴露**：不要将所有方法都设为 public，只暴露必要的接口

### 3.4 常见错误和修复
- **错误**：`'ClassName.MethodName' is inaccessible due to its protection level`
- **原因**：尝试调用 private/protected/internal 方法
- **修复**：
  1. 检查方法访问权限
  2. 如果方法应该是 public，修改访问权限
  3. 如果需要外部调用但不想暴露内部实现，提供 public 包装方法

## 4. 泛型集合规则（重要！）

### 4.1 必须引入泛型命名空间
- **使用泛型集合时必须引入 `using System.Collections.Generic;`**
- 包括：`List<>`, `Dictionary<>`, `HashSet<>`, `Queue<>`, `Stack<>` 等

**示例：**
```csharp
// ❌ 错误：缺少命名空间
public class MyClass
{
    private List<int> items; // 错误：List<> 需要 using System.Collections.Generic;
}

// ✅ 正确：引入命名空间
using System.Collections.Generic;

public class MyClass
{
    private List<int> items; // 正确
}
```

## 5. Unity MCP工具使用规则

### 5.1 MCP连接检查
- **Unity MCP 未连接时，必须征询用户意见**
- **不能自作主张创建脚本或修改文件**
- 必须先询问用户是否同意，再执行操作

## 6. 功能实现规则（重要！）

### 6.1 只实现用户要求的功能
- **严格按照用户需求实现，不要自作主张扩展功能**
- **不要添加用户没有要求的功能或特性**
- **不要添加"可能有用"但用户没有明确要求的功能**
- 如果认为需要扩展功能，必须先询问用户意见

**示例：**
```csharp
// 用户要求：实现一个简单的拖拽系统
// ❌ 错误：自作主张添加了预览动画、音效、粒子效果等用户没有要求的功能
public class DragSystem
{
    public void PlayDragSound() { ... } // 用户没要求
    public void ShowParticleEffect() { ... } // 用户没要求
    public void AnimatePreview() { ... } // 用户没要求
}

// ✅ 正确：只实现用户要求的拖拽功能
public class DragSystem
{
    public void OnDragBegin() { ... } // 用户要求的
    public void OnDragUpdate() { ... } // 用户要求的
    public void OnDragEnd() { ... } // 用户要求的
}
```

### 6.2 功能扩展原则
- **如果认为某个功能有用，必须先询问用户**
- **不要假设用户需要某些功能**
- **保持实现简洁，只包含必要的代码**

## 7. 编程范式与规范

### 7.1 代码组织
- 保持代码简洁，避免过长的方法
- 将调试代码分离到独立脚本
- 遵循单一职责原则

### 7.2 错误处理
- 使用 `Log.Info`、`Log.Warning`、`Log.Error` 进行日志记录
- 在关键操作前检查空引用
- 提供有意义的错误信息
